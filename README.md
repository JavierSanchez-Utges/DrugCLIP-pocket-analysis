## Overview

This work benchmarks DrugCLIP-style pocket embeddings under a series of pocket-source
perturbations — apo/holo/AlphaFold-predicted structures, P2Rank-detected pockets, and random
surface patches — against experimental, ligand-defined pockets, and asks how much retrieval
performance degrades as the pocket definition moves away from the ideal case. It draws on three
underlying projects:

- **DrugCLIP pocket-source robustness** (`CHEMBL_DRUGCLIP`) — apo/holo/AFDB structure and
  P2Rank/random-patch pocket-detection perturbations, scored against experimental pockets and
  pooled across the coach420 / holo4k / pdbbind2020 / scPDB datasets.
- **Pocket-matching benchmark** (`POCKET_MATCHING_BENCHMARK`) — the PROSPECCTS pocket-similarity
  benchmark, comparing DrugCLIP-derived scores against PocketVec, NRGRank and EPoCS, plus naive
  sequence/ligand-identity baselines.
- **Natural-ligand embedding analysis** (`NATURAL_LIGANDS`) — pocket/ligand embedding geometry,
  embedding-vs-structural-similarity relationships, and training-set de-leakage analysis for the
  screening benchmark.

Notebooks are numbered as in their original projects and kept flat in one folder; the number

no local path configuration needed.

This repository holds **code only** — `DATA/` is git-ignored and not pushed to GitHub. The data
itself (the **minimal reproducing input set** for these 15 notebooks, ~5.6 GB, curated down from
the ~263 GB of combined raw/intermediate output across the three source projects) is archived
separately on Zenodo:

To reproduce the analysis, download the Zenodo archive and extract it as `DATA/` at the repo root
(i.e. so `DATA/drugclip/`, `DATA/pocket_benchmark/` and `DATA/natural_ligands/` sit directly under
this repo, alongside `ANALYSIS/`) — every notebook resolves its paths relative to the repo root, so
no further configuration is needed.

`DATA/` does not include:

- Full raw pipeline outputs (P2Rank runs, structure downloads, embedding caches for datasets/
  ligand codes not touched by these specific notebooks) — those live in a separate, larger Zenodo
  deposit for full from-scratch provenance (**link TODO**).
- Intermediate files these notebooks *regenerate themselves* when run in order (e.g. the pooled/
  deduplicated TSVs written by notebooks 45, 46 and 49, and read back by 47/48 and 50/51).

One exception: `DATA/drugclip/RESULTS/afdb_pockets_6A/afdb_vs_exp_scores_pooled_dedup.tsv` is a
precomputed artifact generated by an upstream notebook (`37b_afdb_vs_experimental_scores_6A_pooled`)
that isn't included in this repository; it's shipped directly since notebooks 47 and 48 need it as
an input.

## External dependencies

These notebooks compare against, or build on data produced by, the following external methods,
tools and databases. They aren't Python packages (so aren't in `environment.yml`) — this is for
provenance/citation, not something you need to install to run the notebooks as shipped (their
outputs are already baked into `DATA/`), except where noted.

1. [P2Rank](https://github.com/rdk/p2rank) — pocket-detection method whose predictions are
   compared throughout (PDB and AlphaFold-model structures).
2. [DrugCLIP](https://github.com/bowen-gao/DrugCLIP) — the contrastive pocket/ligand embedding
   model this whole analysis evaluates. Gao B, *et al.* "DrugCLIP: Contrastive Protein-Molecule
   Representation Learning for Virtual Screening." *NeurIPS* 2023.
3. [AlphaFold Protein Structure Database](https://alphafold.ebi.ac.uk/) — source of the predicted
   structures used in the AFDB pocket-source robustness experiments.
4. **ProSPECCTs** — the pocket-matching benchmark dataset used in notebooks 00/02/04. Ehrt C,
   Brinkjost T, Koch O. "A benchmark driven guide to binding site comparison: An exhaustive
   evaluation using tailor-made data sets (ProSPECCTs)." *PLOS Comput Biol.* 2018;14(11):e1006483.
   [doi:10.1371/journal.pcbi.1006483](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1006483).
5. [PocketVec](https://github.com/sbnb-irb/pocketvec) — pocket-comparison method compared in
   notebook 02. Duran-Frigola *et al.* "Comprehensive detection and characterization of human
   druggable pockets through binding site descriptors." *Nat Commun.* 2024.
   [doi:10.1038/s41467-024-52146-3](https://www.nature.com/articles/s41467-024-52146-3).
6. **NRGRank** — pocket/ligand scoring method compared in notebook 02.
   [bioRxiv 2025.02.17.638675](https://www.biorxiv.org/content/10.1101/2025.02.17.638675v1.full).
7. [EPoCS](https://github.com/tugceoruc/epocs) — ESM-2-based pocket cross-similarity method
   compared in notebook 02. Oruç T, *et al.* "Mapping the space of protein binding sites with
   sequence-based protein language models." *Bioinformatics.* 2025;41(6):btaf284.
   [doi:10.1093/bioinformatics/btaf284](https://academic.oup.com/bioinformatics/article/41/6/btaf284/8176567).
8. [US-align](https://github.com/pylelab/USalign) — structural alignment tool used upstream to
   compute the SC-RMSD values shipped in `DATA/` (not re-run by these notebooks). Zhang C, *et al.*
   "US-align: universal structure alignments of proteins, nucleic acids, and macromolecular
   complexes." *Nat Methods.* 2022.
   [doi:10.1038/s41592-022-01585-1](https://www.nature.com/articles/s41592-022-01585-1).
9. [MMseqs2](https://github.com/soedinglab/MMseqs2) — used upstream to compute pocket/receptor
   sequence identity (shipped in `DATA/`, not re-run by these notebooks).
10. [RCSB PDB](https://www.rcsb.org/) / Chemical Component Dictionary — queried live by notebook
    04 to resolve ligand identity for structures whose HETATM records were anonymised.
11. [Uni-Mol](https://github.com/deepmodeling/Uni-Mol) — molecular representation framework behind
    the CCD/ligand manifests used for embedding-vs-similarity comparisons.
12. [BioLiP2](https://zhanggroup.org/BioLiP/) — source database for the DrugCLIP training-set
    ligand union used in de-leakage analysis (notebook 26, 52).
13. [SIFTS](https://www.ebi.ac.uk/pdbe/docs/sifts/) — PDB-to-UniProt residue-level mapping,
    underlying the AFDB structure lookups.

## Run order

Most notebooks are self-contained given the shipped `DATA/`, but a few have dependencies within
this notebook set:

- **45 → 47, 48** and **46 → 47, 48**: notebooks 45/46 write the pooled apo/holo TSVs that 47 and
  48 read (alongside the precomputed AFDB artifact above). Run 45 and 46 before 47/48.
- **49 → 50, 51**: notebook 49 writes the pooled PDB-P2Rank / AFDB-P2Rank / patches TSVs that 50
  and 51 read. Run 49 first.
- **02 → 04 → 02**: notebook 02 (PROSPECCTS benchmark) and 04 (naive baselines) have a circular
  dependency — 02 first produces `prospeccts_benchmark_dfs.pkl` without the baseline columns, 04
  reads it and adds baseline scores, and 02 needs a second pass to merge those columns back in and
  regenerate its final summary tables/figures. Run **02 → 04 → 02** in that order; then 00 (a
  read-only QC notebook) can be run, since it cross-checks against 02's output.
- **00, 20, 24, 25, 26, 52**: no dependency on other notebooks in this set — each runs standalone
  against the shipped `DATA/`.

## Known limitations

Notebook **49** (`p2rank_patches_pooled`) builds on an AlphaFold-DB P2Rank pocket-detection run
that has two known, deliberately-unfixed issues:

1. The AFDB benchmark's P2Rank pass used the plain `default` config rather than `-c alphafold` (or
   `alphafold_conservation_hmm`), which is calibrated for crystal structures rather than AlphaFold
   models.
2. A minority of scPDB/PDBbind2020-derived pockets have an incorrect chain→UniProt mapping (scPDB
   and PDBbind2020 both relabel their single extracted chain as `"A"` regardless of the real
   deposited chain), causing the wrong AlphaFold model to be fetched for those pockets.

Both were root-caused and found not to change the qualitative conclusions (a small minority of the
~14k-pocket AFDB pool is affected), but the exact recall/enrichment figures from AFDB P2Rank in
this benchmark should be treated as provisional pending a rerun with the corrected configuration
and chain mapping.
